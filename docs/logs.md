# logs

`ecsh logs` は、この Mac で `run` したコマンドの出力を見る。

```sh
ecsh logs                 # プロファイルを選び、その履歴から選ぶ
ecsh logs staging         # プロファイルの一覧を飛ばす
ecsh logs --last          # プロファイルを問わず、直近の 1 件をすぐ開く
ecsh logs staging --last  # staging の直近の 1 件を開く
ecsh logs --open          # 出力を流す代わりに CloudWatch Logs のページを開く
```

## 選び方

- 他のコマンドと同じくプロファイルを聞いた後、そのプロファイルの run を新しい順に並べる。各行は、起動時刻・結果（終了 <終了コード>、止まったが終了コードが無ければ（タスクの起動に失敗したなど） 終了コードなし、ecsh がタスクの停止を見届けていなければ 未確認）・所要時間・コマンド
- ↑↓ と Enter で選ぶ（Esc で、終了コード 1 でやめる）
- stdin がターミナルでないときは一覧を出せない。その場合は `--last` を使う
- 見せる run が無ければ、その旨を出して 0 で終わる

## 選んだ run の見せ方

AWS の呼び出しには、履歴に残った `aws_profile` を使う。ただし環境変数 `AWS_PROFILE` があれば、そちらが優先する（設定から選ぶときと同じ順）。

- 終わっている run: 出力を全部 stdout に出し、続けて終了コードと所要時間を stderr に出す
- まだ動いている run: `run` で待つときと同じく出力を流し、タスクが止まったら終了コードを出す。Ctrl-C（ターミナルを閉じる・SIGTERM も）は見るのをやめるだけで、タスクは動き続ける。`logs` は 128 + シグナル番号で終わる
- `-d` で起動した run や止めずに抜けた run は、履歴に終了コードがまだ無い。`logs` が ECS に問い合わせ（DescribeTasks）、タスクが止まっていれば結果を履歴に書く。ECS は止まったタスクをしばらくすると忘れるので、その後は終了コードは不明と出る
- ログストリームがもう無ければ（ロググループの保持期間を過ぎたなど）、出力が残っていないと出す

run を見せ終われば、コマンドの終了コードにかかわらず 0 で終わる。

## --open

`--open` は、出力を出す代わりに、run のログストリームを CloudWatch Logs のコンソールでブラウザに開く（`ecsh logs --open`・`ecsh logs --last --open`）。ログストリームが残っていれば、終わった run にも使える。ブラウザの開き方と AWS のサインインの注意は [open.md](open.md#ブラウザ) を参照。

## 履歴

- 履歴は状態ディレクトリ（`sessions/` と同じ。[exec.md](exec.md#ロックファイル)）の `history.jsonl`
- `run` はタスクを起動するたびに 1 行足し、タスクの停止を見届けたら終了コードと所要時間を書く
- 最新の 100 件だけを残す
- `exec` は記録しない。タスクが `sleep` を動かすだけだから
- 一覧に出るのは、この Mac から起動した run だけ
