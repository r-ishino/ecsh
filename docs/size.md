# タスクの大きさ

`exec` と `run` は、既定ではタスク定義の CPU とメモリでタスクを起動する。起動 1 回分だけ変えたいときは、一覧から選ぶか直接指定する。

## 一覧から選ぶ（--size）

```sh
ecsh exec --size   # プロファイルを選んだ後、大きさを選ぶ
ecsh run --size -- bundle exec rake users:import
```

- 一覧の先頭は「タスク定義のまま」（今の値付き）で、Enter で何も変えずに起動に進む
- 残りは 0.5 vCPU / 1 GB・1 vCPU / 2 GB・1 vCPU / 4 GB・2 vCPU / 4 GB・2 vCPU / 8 GB・4 vCPU / 8 GB・4 vCPU / 16 GB。一覧は組み込みで、設定では変えられない
- `-y`・`--cpu`・`--memory` とは併用できない。一覧を出すので、stdin がターミナルである必要がある

## 直接指定する（--cpu / --memory）

一覧に無い大きさは、`--cpu`（vCPU で。`2`・`0.5` など）と `--memory`（単位付きで。`8GB`・`512MB` など。1 GB = 1024 MiB）で指定する。

```sh
ecsh exec --cpu 2 --memory 8GB
ecsh run --memory 4GB -- bundle exec rake users:import   # CPU はタスク定義のまま
```

- 片方だけ指定すると、もう片方はタスク定義の値
- 起動の前に、Fargate が受け付ける CPU とメモリの組み合わせかを確かめる。受け付けない組み合わせなら、その CPU で指定できるメモリの範囲を添えて弾く
- `-y` と併用できる

## 起動のとき

- 選んだ大きさは y/N の前と、y/N の問いそのものに出る
- タスク定義と同じ大きさなら、何も上書きしない
- 大きさを変えるには `ecs:DescribeTaskDefinition` の権限が要る
- 上書きした大きさは `ps` の CPU・メモリの列にも出る（[ps.md](ps.md#表)）

## コンテナの値の調整

タスクの大きさだけを変えると、大きくしたタスクでもコンテナの古いハードリミットで頭打ちになり、小さくしたタスクはコンテナが収まらずに弾かれる。そこで、タスク定義がプロファイルのコンテナに `memory`（ハードリミット）・`memoryReservation`・`cpu` を設定していれば、そのコンテナの値も新しいタスクの大きさに合わせて直す。

- ハードリミットと `cpu` は、タスクの値から、タスク内の他のコンテナ（サイドカー）が設定している分を引いた値にする
- `memoryReservation` は、収まらなくなったときだけ下げる
- 他のコンテナはそのまま
- サイドカーだけで新しい大きさが埋まる（残りが 0 以下になる）なら、タスクを起動する前に失敗する。これを確かめるのは、プロファイルのコンテナ自身が値を設定している項目だけ（メモリなら `memory` か `memoryReservation`、CPU なら `cpu`）
